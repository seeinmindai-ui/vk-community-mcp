# Инструкции разработки

Проект: VK Community MCP. Карта — README.md, решения — документы/Обслуживание.md и документы/Источники и лицензии.md.

- Сохраняйте привязку пользователь → разрешённое сообщество → токен. Никогда не принимайте owner_id/токен из аргументов MCP.
- Не добавляйте произвольные HTTP/API/shell/файловые инструменты.
- Изменения VK требуют отдельного браузерного подтверждения неизменяемых параметров; model-supplied confirm не считается согласием человека.
- Проверяйте совместимость официального SDK и OAuth: PKCE, resource, scope, expiry, refresh/replay.
- Секреты и реальное состояние только вне репозитория. Не открывайте vault.key, service.sqlite, .env, пользовательские auth-файлы и чужие Keychain-записи.
- Перед публикацией: `python -m unittest discover -s tests -v`, `python scripts/check_publication.py`; проверьте лицензию каждой новой зависимости.
- Автономные тесты используют фиктивные данные. Не вызывайте реальные публикации, отправку сообщений, удаление или изменение настроек VK без отдельного конкретного поручения.
- Развёртывание на существующий VPS: отдельный сервис и loopback порт. Сохраняйте Caddy/DNS/чужие подключения. Для новой установки нужно явное разрешение владельца экземпляра.
- Обновления production требуют пройденных проверок, предыдущего релиза для отката и health-проверки. Не расширяйте права автоматически.
- Документы для человека пишите по-русски. Не называйте весь каталог API проверенным по одной схеме или по tools/list.
